3 LLM Contract — Shared Interface

All 5 provider clients implement this contract from packages/llm-contract:

interface LLMClient { research(prompt: string): Promise<Result<ResearchResult, LLMError>>; generate(prompt: string): Promise<Result<GenerateResult, LLMError>>; generateImage?(prompt: string, options?: ImageGenerateOptions): Promise<Result<ImageGenerationResult, LLMError>>; } type ResearchResult = { content: string; sources: string[]; usage: NormalizedUsage } type GenerateResult = { content: string; usage: NormalizedUsage } type ImageGenerationResult = { imageData: Buffer; model: string; usage: NormalizedUsage } type NormalizedUsage = { inputTokens: number; outputTokens: number; totalTokens: number; costUsd: number; cacheTokens?: number; // Claude prompt caching reasoningTokens?: number; // o4-mini reasoning webSearchCalls?: number; // Claude, GLM web search groundingEnabled?: boolean; // Gemini grounding } type LLMErrorCode = 'API_ERROR' | 'TIMEOUT' | 'INVALID_KEY' | 'RATE_LIMITED' | 'OVERLOADED' | 'CONTEXT_LENGTH' | 'CONTENT_FILTERED' type LLMError = { code: LLMErrorCode; message: string }

8 Support Packages
FAC
llm-factory
createLlmClient(config) → LlmGenerateClient
What it does
Selects provider based on model name via getProviderForModel(). Only supports Google and Zai. Claude, GPT, and Perplexity are NOT available through the factory.
Why limited?
The factory is used via UserServiceClient.getLlmClient(userId) which resolves user's preferred model. Default fallback is gemini-2.5-flash or glm-4.7-flash.
AUD
llm-audit
createAuditContext() → AuditContext
What it does
Called before EVERY LLM request. Creates an audit trail in Firestore with provider, model, method, prompt, timing, tokens, cost. Controlled by INTEXURAOS_AUDIT_LLMS env var.
$$$
llm-pricing
createUsageLogger() → UsageLogger
What it does
Fetches pricing from app-settings-service, creates PricingContext for O(1) lookups. Logs usage to Firestore llm_usage_stats collection (total / monthly / daily / per-user).
PRM
llm-prompts
PromptBuilder pattern with version tracking
What it does
All prompts follow PromptBuilder<TInput, TDeps> pattern: { name, description, version, build() }. Versioned via semver. Domains: classification, generation, research, synthesis, calendar, linear, todos, dataInsights, image, validation, approvals.
UTL
llm-utils
Error handling + token redaction utilities
What it does
Redacts API keys from logs (redactToken()). Provides LLM JSON parse error handling with Zod schema formatting (formatZodErrors()). Used across all agents when parsing structured LLM output.
INT
internal-clients
UserServiceClient.getLlmClient(userId)
The Gateway
Standard way apps get LLM clients: 1) Reads user's defaultModel preference, 2) Gets API key for that provider, 3) Falls back to platform keys (Gemini/GLM), 4) Calls createLlmClient() from llm-factory. This is why most apps only see Gemini or GLM.

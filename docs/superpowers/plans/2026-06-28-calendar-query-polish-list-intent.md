# Calendar Query Polish List Intent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the Intex WhatsApp Assistant route Polish calendar event list requests like `Podaj listę wszystkich wydarzeń, które mam jutro w kalendarzu` to the existing `query_calendar_events` tool.

**Architecture:** The calendar query endpoint, internal client, tool executor, and prompt added by INT-1697 are already present. The primary defect is in the Intex Agent intent gate: the exact Polish list wording is classified as ordinary conversation, so the runner exposes zero tools and the model returns an unsupported reply. The secondary defect is that unsupported/capability replies can be generated by the model and drift from the real tool inventory; the fix centralizes a deterministic point-list of capabilities and uses it for unsupported/fallback replies.

**Tech Stack:** TypeScript, Vitest, Fastify service architecture, `@intexuraos/llm-contract` tool-calling abstractions, `@intexuraos/internal-clients` calendar-agent client.

```json
  }

```

There is no `tool_call_completed` event in that session, so the calendar-agent read endpoint was never reached.

**Local reproduction:** Running the classifier against the exact phrase returns conversation instead of tool:

```json
{
  "text": "Podaj listę wszystkich wydarzeń, które mam jutro w kalendarzu",
  "decision": { "kind": "no_action", "reason": "conversation" }
}
```

Nearby phrases already covered by tests route correctly:

```json
{
  "text": "Chciałbym zobaczyć, jakie mam wydarzenia w kalendarzu na jutro",
  "decision": { "kind": "tool", "allowedToolNames": ["query_calendar_events"] }
}
```

**Root cause:** `apps/intex-agent/src/domain/agent/intentGate.ts` normalizes `listę` to `liste`, but `isReadOnlyCalendarQueryRequest()` only treats English `list` and Polish verbs like `pokaz`, `sprawdz`, `zobac`, `znajdz`, `szukaj`, and `co jest` as list intent. It does not include `podaj`, `lista`, `liste`, or `listy`. Because the runner filters tools with `intent.kind === 'tool'`, a `no_action` decision gives the model zero tools.

```typescript
const tools = createIntexAgentToolDefinitions(
  createTrackingToolExecutor(config.toolExecutor, toolExecutions)
).filter(
  (tool) =>
    intent.kind === 'tool' && intent.allowedToolNames.includes(tool.name as IntexAgentToolName)
);
```

- [ ] **Step 1: Add a centralized capability-list module**

Create `apps/intex-agent/src/domain/agent/capabilities.ts`:

```typescript
export const INTEX_AGENT_CAPABILITIES = [
  'create notes',
  'create and look up calendar events',
  'create research drafts',
  'save bookmarks',
  'create code tasks for planning or execution',
] as const;

export function buildCapabilitiesReply(intro: string): string {
  return [intro, ...INTEX_AGENT_CAPABILITIES.map((capability) => `- ${capability}`)].join('\n');
}

export function buildUnsupportedCapabilitiesReply(): string {
  return buildCapabilitiesReply('I could not safely handle that request. I can help with:');
}

export function buildCompletionFailureCapabilitiesReply(): string {
  return buildCapabilitiesReply('I could not complete that request right now. I can help with:');
}

export function buildNewSessionReadyText(): string {
  return buildCapabilitiesReply('What would you like me to help with? I can help with:');
}
```

This groups the six tool definitions from `createIntexAgentToolDefinitions()` into the five user-facing capability buckets the assistant should mention. The `create_calendar_event` and `query_calendar_events` tools share the calendar bucket. The code-task bucket says `create code tasks for planning or execution` instead of `execute code tasks` because the tool creates a task and can set `taskMode: 'execution'`; the WhatsApp assistant does not directly execute code inline.

# Local Dev Environment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the local development environment a first-class project environment that starts all services with auto-reload, uses synced dev secrets, and supports automated login tests.

**Architecture:** Keep local simple: PM2 runs app services from TypeScript sources with watch enabled, Vite serves web, Docker runs only the Pub/Sub emulator and Pub/Sub UI. Local uses the shared GCP project for Firestore/Storage/Secret Manager and local Pub/Sub emulator aliases for message flow.

**Tech Stack:** Node.js, pnpm 10.29.3, PM2, Docker Compose, Auth0, GCP Secret Manager, Firestore.

## Global Constraints

- No git worktrees; project rules require a normal feature branch.
- Secrets are synced from GCP Secret Manager into `.envrc`; `.envrc` and `.envrc.local` remain ignored.
- Local PM2 services must not inherit `FIRESTORE_EMULATOR_HOST` or `STORAGE_EMULATOR_HOST`.
- Local PM2 services must use `PUBSUB_EMULATOR_HOST=localhost:8102`.
- Login credentials are stored outside the repo in `~/.intexuraos/logins.md` and are intended to work across local, dev, and prod because all environments share the Auth0 tenant/configuration.

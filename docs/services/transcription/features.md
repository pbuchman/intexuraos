# Transcription Worker

> **Migration note:** Voice transcription has been part of IntexuraOS since v2.x (originally inline in whatsapp-service using Speechmatics). In v3.2.0, transcription was extracted into this dedicated Cloud Function worker with event-driven processing via Pub/Sub.

Convert WhatsApp voice notes into searchable text — automatically, accurately, and in any language.

## The Problem

Users send voice notes through WhatsApp to capture thoughts hands-free, but audio content is trapped in an opaque format. You cannot search it, skim it, or act on it without replaying the entire recording. The system needs a way to convert audio into structured text so downstream services can extract tasks, generate summaries, and enable full-text search.

## How It Helps

### Automatic Voice-to-Text Conversion

Every voice note stored in GCS triggers transcription without manual intervention. The worker picks up audio files the moment they are stored and delivers text back through Pub/Sub.

**Example:** A user records a 45-second voice note while driving. Within minutes, the transcription is complete and the whatsapp-service receives the full text, ready for task extraction.

### AI-Generated Summaries

Each transcription includes a brief paragraph summary generated by Speechmatics. Long, rambling voice notes get distilled into concise overviews that capture the key points.

**Example:** A 3-minute voice note about project updates produces both the full transcript and a one-paragraph summary highlighting the three action items mentioned.

### Automatic Language Detection

The worker detects the spoken language without any configuration. Users can speak in Polish, English, or switch mid-sentence — the system handles it transparently.

**Example:** A bilingual user records a voice note mixing Polish and English technical terms. The worker detects the language and returns both the transcript and the detected language code for downstream routing.

### Custom Vocabulary for Technical Accuracy

A built-in vocabulary of 100+ domain-specific terms ensures accurate transcription of IntexuraOS-specific words, AI/LLM terminology, cloud platform names, Polish-English code-mixed verbs, and development tool names.

**Example:** A voice note mentioning "IntexuraOS", "pnpm", "Claude Opus", or "commitowac" is transcribed correctly instead of producing garbled approximations.

## Use Case

A user is walking and remembers three things they need to do for their IntexuraOS project. They open WhatsApp, record a voice note: "I need to pushowac the changes to the monorepo, check the Sentry alerts for the calendar-agent, and create a Linear issue for the Firestore migration."

The whatsapp-service stores the audio in GCS and publishes an `audio-stored` event. The transcription worker picks it up, generates a signed URL for the audio file, submits it to Speechmatics with the custom vocabulary, polls until complete, and publishes the transcript. The whatsapp-service receives the text and passes it to the commands-agent for task extraction — all within minutes, with every technical term spelled correctly.

## Key Benefits

- Zero-touch processing: audio files are transcribed automatically on arrival
- Enhanced accuracy through domain-specific custom vocabulary
- Language-agnostic: works with any spoken language, auto-detected
- AI summaries reduce time spent reading long transcriptions
- Resilient error handling: always publishes a result, even on failure

## Limitations

- Only processes audio from WhatsApp (triggered by `whatsapp.audio.stored` events)
- Currently supports only Speechmatics as a transcription provider (provider factory is extensible but no alternatives are implemented)
- Polling-based completion check with exponential backoff can take up to ~5 minutes for long audio files
- Speechmatics rate limits and quotas apply (service handles these gracefully but cannot bypass them)
- No real-time streaming transcription — batch processing only

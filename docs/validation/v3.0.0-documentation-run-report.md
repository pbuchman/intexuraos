# v3.0.0 Documentation Run Report

**Date:** 2026-02-08
**Branch:** development (vs origin/main)
**Method:** Multi-agent autonomous documentation with cross-validation
**Duration:** ~45 minutes (34 agents in parallel)

---

## Executive Summary

The v3.0.0 documentation run is the first full-scale multi-agent documentation effort for IntexuraOS. It covered all 51 components in the monorepo (25 apps, 5 workers, 21 packages), producing 193 documentation files and 6 cross-validation reports. The run discovered **1 production bug** (missing IAM permission), **12 HTTP contract discrepancies**, **7 Pub/Sub inconsistencies**, **12 AI model documentation issues**, **7 Firestore naming discrepancies**, **6 package dependency documentation gaps**, and **14 environment variable mismatches**.

## Phase 4: Cross-Validation Results

Six validation domains were independently audited by dedicated agents. Each agent started from documentation and traced claims back to actual code/infrastructure.

### 4.1 HTTP Contracts

**Report:** `docs/validation/http-contracts-validation.md`
**Scope:** 52 internal endpoints across 15 services

| Severity | Count | Examples                                                      |
| -------- | ----- | ------------------------------------------------------------- |
| HIGH     | 2     | code-agent cancel path wrong, cleanup-logs path wrong         |
| MEDIUM   | 2     | actions-agent PATCH undocumented, 3 linear-agent endpoints    |
| LOW      | 8     | Phantom `/llm-client` endpoint in 4 services, path mismatches |

**Key Findings:**

- **D6:** `POST /internal/code/cancel` in docs but actual path is `/internal/code/cancel-with-nonce` -- would cause 404
- **D7:** `POST /internal/code/cleanup-logs` in docs but actual path is `/internal/tasks/cleanup-logs` -- would cause 404
- **D1:** 4 services reference phantom `/internal/users/:id/llm-client` endpoint (doesn't exist; the `@intexuraos/internal-clients` package calls two separate user-service endpoints)
- **D4:** `PATCH /internal/actions/:actionId/status` exists in code but not in actions-agent docs table
- **D5:** 3 linear-agent endpoints exist in code but omitted from Internal Endpoints table

### 4.2 Pub/Sub Contracts

**Report:** `docs/validation/pubsub-contracts-validation.md`
**Scope:** 14 topics, all Terraform modules, all publisher/subscriber relationships

| Severity | Count | Examples                                                      |
| -------- | ----- | ------------------------------------------------------------- |
| HIGH     | 1     | **PRODUCTION BUG:** code-agent missing IAM publish permission |
| MEDIUM   | 1     | Phantom `whatsapp-linkpreview` topic in docs                  |
| LOW      | 5     | Stale service names, incomplete env var table, naming issues  |

**Key Findings:**

- **D5 (PRODUCTION BUG):** code-agent publishes to `whatsapp-send` topic but Terraform's `publisher_service_accounts` does not include `code_agent`. This means WhatsApp notifications for code tasks will fail with `PERMISSION_DENIED` in production.
- **D1:** whatsapp-service docs claim a separate `whatsapp-linkpreview` topic that doesn't exist -- link preview events use the `webhook-process` topic with event type routing
- **D2:** `pubsub-standards.md` references `llm-orchestrator` and `commands-router` -- services that don't exist
- **Naming:** `INTEXURAOS_TODOS_PROCESSING_TOPIC` doesn't follow `INTEXURAOS_PUBSUB_*` convention

### 4.3 AI Models

**Report:** `docs/validation/ai-models-validation.md`
**Scope:** 18 models across 5 providers, all service docs vs `llm-contract` source of truth

| Severity | Count | Examples                                                |
| -------- | ----- | ------------------------------------------------------- |
| HIGH     | 4     | 2 unregistered models, 2 missing services from overview |
| MEDIUM   | 5     | Model naming inconsistencies, wrong AI attribution      |
| LOW      | 3     | Cosmetic naming variations                              |

**Key Findings:**

- **Unregistered models:** `gpt-4.1` (image-service) and `text-embedding-3-small` (chat-agent) are used in production but not in `llm-contract` registry
- **Count contradiction:** overview.md says "17 models" then "16 models" -- actual is 16 in llm-contract, 18 total in use
- **Model ID confusion:** research-agent docs use `claude-opus-4.5` (invalid short form) instead of `claude-opus-4-5-20251101`
- **Wrong attribution:** index.md says todos-agent uses AI "Via commands-agent" -- actually makes its own LLM calls
- **Missing services:** chat-agent and code-agent not in overview.md or index.md service tables

### 4.6 Environment Variables

**Report:** `docs/validation/env-vars-validation.md`
**Scope:** 10 services checked against 4 sources (docs, REQUIRED_ENV, Terraform, ecosystem.config.cjs)

| Severity | Count | Examples                                                  |
| -------- | ----- | --------------------------------------------------------- |
| CRITICAL | 1     | whatsapp-service docs have completely wrong env var names |
| HIGH     | 2     | user-service docs: 4 false positives + 6 missing vars     |
| MEDIUM   | 4     | Auth vars systematically omitted from 6+ service docs     |
| LOW      | 7     | Minor naming inconsistencies, optional vars undocumented  |

**Key Findings:**

- **whatsapp-service CRITICAL:** Every Pub/Sub and credential env var name in docs differs from actual code. Example: docs say `INTEXURAOS_APP_SECRET`, code uses `INTEXURAOS_WHATSAPP_APP_SECRET`
- **Systemic issue:** `INTEXURAOS_AUTH_JWKS_URL`, `INTEXURAOS_AUTH_ISSUER`, `INTEXURAOS_AUTH_AUDIENCE`, `INTEXURAOS_GCP_PROJECT_ID` are in REQUIRED_ENV for most services but consistently omitted from documentation
- **user-service:** 4 env vars listed as required in docs are NOT in REQUIRED_ENV (possibly deprecated). 6 vars ARE in REQUIRED_ENV but not documented.
- **Naming violation:** orchestrator uses `INTEXURAOS_PROJECT_ID` while all others use `INTEXURAOS_GCP_PROJECT_ID`

## Observations

### What Worked Well

1. **Parallel agent execution** -- 34 agents completed in ~45 minutes vs estimated 8+ hours sequential
2. **Opus for greenfield** -- New services got richer, more thorough documentation
3. **Sonnet for updates** -- Existing docs preserved user insights while updating efficiently
4. **Docs-first validation** -- Starting from documentation and tracing to code caught mismatches that code-first would miss
5. **Cross-service validation** -- Found a real production IAM bug that no single-service documentation effort would have caught
6. **Package documentation** -- First time all 21 packages documented; revealed systemic gap in dependency table documentation

### Systemic Patterns Discovered

1. **Phantom endpoint pattern:** Multiple services document a `/llm-client` convenience endpoint that doesn't exist -- the `@intexuraos/internal-clients` package abstracts this into two separate calls. Docs should reference the package, not a phantom endpoint.

2. **Auth vars omission:** Nearly every service omits `AUTH_JWKS_URL`, `AUTH_ISSUER`, `AUTH_AUDIENCE`, `GCP_PROJECT_ID` from their env var documentation. These are "boring" common vars but their absence is misleading. Recommendation: either document them everywhere or add a "Plus standard common env vars (see reference)" note with a link.

3. **LLM factory limitation:** The `llm-factory` package only supports Google and Zai providers. Services needing Anthropic, OpenAI, or Perplexity create clients directly. This isn't a bug but should be documented prominently in the llm-factory README.

4. **Model registry gap:** Two models (`gpt-4.1`, `text-embedding-3-small`) are used in production but not registered in `llm-contract`. This means they aren't tracked by `llm-pricing` for cost analytics.

### Recommendations for Next Run

1. **Fix production bug first** -- Add `code_agent` to `pubsub_whatsapp_send.publisher_service_accounts` in Terraform
2. **Standardize env var documentation** -- Create a "common env vars" reference doc and link from each service
3. **Register all models** -- Add `gpt-4.1` and `text-embedding-3-small` to `llm-contract` or document why excluded
4. **Fix whatsapp-service docs** -- Every env var name is wrong; this is the worst single documentation gap
5. **Add cross-validation as a permanent CI check** -- The validation reports could be automated into a docs-lint step
